# Prefixed UUIDv7 public ids

Every record exposed by the API has a UUIDv7 primary key generated by Postgres 18's native `uuidv7()`, and the API shows it with a type prefix (`doc_<uuid>`, `ext_<uuid>`, `evt_<uuid>`). UUIDv7 is time-ordered, so it indexes well and supports cursor pagination on `(created_at, id)`; the prefix makes ids self-describing in logs and support tickets, and a lookup with the wrong prefix returns 404, which catches a document id passed where an extraction id belongs. Clients store these ids forever, so the format cannot change after launch.

## Considered Options

- **Plain UUIDs**: simplest, but an id on its own says nothing about what it identifies.
- **Prefixed ULIDs** (as in the original spec's examples): same benefits, but needs a gem or custom type where UUIDv7 is native to Postgres 18.
